# ADR-012 — Resposta HTTP de erro é preservada como prova

- **Situação:** proposta — tomada durante a Fase 0, aguarda revisão
- **Data:** 2026-09-29
- **Origem:** implementação da coleta HTTP
- **Código:** `packages/ingestao/lumen_ingestao/coleta_http.py`

## Contexto

O comportamento usual de um coletor é descartar respostas 404 e 503 como
falha. Mas o princípio P5 diz que ausência de dado é informação: um portal
que não publica o que a lei obriga é um achado.

## Decisão

Respostas 4xx e 5xx voltam como artefato completo — status, cabeçalhos e
corpo — e são guardadas na camada bronze como qualquer outra. Só levanta
exceção a falha em que nada foi recebido (DNS, conexão recusada, tempo
esgotado).

## Alternativas consideradas

Tratar erro HTTP como exceção e registrar apenas em log.

## Consequências

O módulo de conformidade passa a ter prova datada para distinguir
indisponibilidade passageira (503 isolado) de ausência persistente (404 em
toda coleta da janela). Log não serve para isso: não é prova, e não é
imutável.

Quem decide se o erro é temporário ou persistente é o avaliador de
conformidade, olhando a sequência de coletas — não o coletor, que vê uma
requisição só.
